# ADR 0005 — Improve autoloop policy under a frozen evaluator

Accepted architecture, 2026-11-28. Applies to explicitly enrolled runs. The increments below are implementation work.

## Context

In `backend-2gb-proof-20261128`, a pooled latency statistic hid a failing sale class, a smoke run could qualify a configuration, and an attempted restart check read the wrong field. A stale checkout passed a gate. Two competing lease authorities invalidated measurements. The coordinator reported p95 values of 2.9 and 10.7 seconds on the same configuration under different contention. Roughly 35 hand-entered attempts tell us where to investigate. They cannot tell us what a different worker would have accomplished on the same assignment, or where most tokens went.

At base `7a562e0`, the skill freezes a contract, checks individual worktrees, integrates their last green commits, then records reviews and safeguards. The guard authenticates the owner on GitHub. Trusted tooling materializes base blobs plus individually approved policy overlays and excludes the shard under check. Static rule registration already substitutes a bad fixture. Resource leases share a Windows authority across clones and WSL, while checkpoint mutexes are per Git common directory. Routing reads external JSONL. Lessons include local drafts. Preserve these distinctions when extending the loop.

## Decision

Optimize **tokens per successfully verified assignment**, subject to exact financial results, security, completion and a dollar ceiling. A 50% reduction is the experimental target. First measure the denominator and consumption. A cheaper failure is still a failure.

### Which steps spend tokens

| Step | Executor and output |
|---|---|
| Intake, scope and success criteria | Owner decides. Tier 0 validates the frozen contract. An optional single model consultation draws from the run budget. |
| Dependencies, admission, context lookup, diff-to-test mapping | Tier 0 topological readiness and lease availability, indexed references and impacted tests. Unknown dependencies select the full relevant suite. Selection accelerates the inner loop only. |
| Discover or implement a solution | Try a known deterministic resolution first. Tier 1 Devin SWE-2.1 handles routine edits/tests. Tier 2 Codex Sol handles complex debugging/performance. Tier 3 Astra handles architecture, adversarial reasoning and financial correctness when needed. |
| Escalation | Tier 0 records an unresolved failure signature after an attempted remedy, or a frozen high-risk task classification requiring expertise at intake. Record reason, next tier and remaining allowance. Repeated identical evidence pauses the run. |
| Execute tests, extract failures, compare benchmarks, settle state and supervise reviews | Tier 0 uses exit status, structured test results, per-class comparators and immutable evidence. An ambiguous failure can consume one budgeted investigation. Enabled review is a source of findings. No model judges a score or grants promotion. |
| Harvest, propose, evaluate, activate | Tier 0 deduplicates verified lessons and screens changes. A worker on an enrolled run may author one scoped proposal. Tier 0 runs comparisons and authenticates owner activation. No resident meta-agent. |

### Metering and shared memory

Collect provider-reported usage keyed by run, shard, delegation, generation, model/version, role, retry, turn/request and tool call when observable. Record cached reads, cache writes where distinct, uncached input, output, reasoning, currency/cost, source, units, inclusion relationships and coverage. Preserve unknowns as null with reason. Reconcile totals once at the finest observed granularity. Reasoning included in output and cached input included in total input must each be counted once. Some tools cause billed tokens only when their results enter the next prompt. Link that call to the turn, record returned bytes separately and leave per-call billed usage unknown unless directly attributed. Estimates stay separate from measured spend.

Use one Tier 0 coordinator-owned index (SQLite with text search and symbol edges) behind a read-only query interface for T3 workers in Windows and WSL. Index tree/blob IDs, symbols, probable calls/imports, accepted ADRs, confirmed lessons, measured bottlenecks, dead ends and regression artifact hashes. Reindex changed blobs and invalidate dependent edges on rename, deletion or parser change. Mark dynamic calls unresolved. Filter by authorized tree, path and evidence provenance. Drafts may suggest searches but cannot acquire verified status without a reproducible artifact. Exclude hidden evidence, tokens, credentials and private logs. Return bounded snippets with source spans, expandable on request.

Deduplicate reads by tree/blob, span and query. Return an existing reference when already delivered to that worker, and reuse indexed excerpts across workers. A new worker still needs the excerpt if its context lacks it. Key failed hypotheses by task, relevant input hashes, normalized failure and attempted remedy. An unchanged retry requires new evidence or owner intervention. Handoffs contain objective, tree, paths/symbols, failed hypothesis IDs, next unresolved question, validation IDs and remaining budget.

### Evidence and admission

Before spawn, a trusted coordinator broker transaction reserves a unique (repo, run, shard, role, generation), request ID, request/brief digest, task class/difficulty, contract revision/hash, policy/epoch, base/head/tree fingerprint, provider/model/settings, limits, expiry and timestamp. Persist before sending the idempotent request to T3. Attach its task ID, including on recovery by request ID. On uncertain dispatch, quarantine and reconcile before allocating another worker. Store the ledger outside clones under a separate coordinator principal. A worktree path check or a Git mutex alone cannot fence other clones or processes sharing the same credentials.

Append an immutable, content-addressed settlement with reservation ID, actual worker identity when exposed, start/end, status, reason, usage/source, gate IDs, before/after SHA and tree, path diff, findings and artifact hashes. Compare-and-swap current generation and published head under a single broker transaction. Revoke on cancellation, expiry, changed contract/base or replacement. Late returns remain cost/diagnostic records and cannot publish. Identical settles are idempotent, conflicting duplicates fail. An unconfirmed spawn is unknown, a proven unstarted reservation is not_run. Derive first/eventual verified acceptance and all spend from settlements plus integration evidence. Import old JSONL once by digest as historical, unverified observations. During migration project the old routing-report columns. Manual entries have no promotion authority.

Reserve worst-case **enforceable** tokens, cost and time before each model call, including retries. Reconcile actuals after settlement. If the provider cannot enforce a per-delegation ceiling, require an enforceable provider/account quota isolated to the campaign or exclude that route from paid campaigns. A wall-clock timeout alone cannot enforce a token limit. No new work after kill, stall or exhaustion. Cancel in-flight tasks, fence publication, retain consume-to-date and settle in-flight reservations conservatively. Record distinct terminal reasons. Keep current strike/replan limits as upper bounds.

### One verification decision

Phase 2 verification owns a Tier 0 content-addressed check cache in the broker store. Integration wires it into existing check entry points. Admit only explicitly allowlisted deterministic commands running with a closed set of inputs. Key by code_tree_sha256, trusted tooling digest, exact argv and working directory, actual interpreter and installed dependency identity plus lock digest, allowed environment names and values, platform/runtime image and cache schema. Include digests for every additional readable input, including files excluded from the code-tree hash. If a command can observe unkeyed state, run it fresh. Live, timing and evaluator checks always run fresh.

On a hit, record a new evidence reference marked cached with the original trusted execution receipt and output digest. Verify the origin, eligibility, key and revocation status on every use. Any mismatch is a miss. Reuse only the check result; recompute current scope, Git ancestry, generations, contract and approvals. Test cold/warm equivalence, mutate each input independently, revoke the source receipt, and prove excluded check types always execute. Measure avoided subprocess time and hit rate.

`verify(target, frozen_contract, evidence_snapshot)` is trusted, deterministic and side-effect free. Targets are ordered obligations: individual shard, integrated gate, review submission, merge eligibility and policy activation. Each adds requirements to its predecessor. A shard can qualify for review before its review exists. Use this same implementation in check (including all-shards), submit, ready-to-merge derivation, CI finalize, recovery and promotion. Callers may gather evidence but cannot reinterpret a failed or missing obligation. At publication, reread the actual Git refs, owner contract/label/comment state, epoch and generation and compare-and-swap the bound tuple. On a race invalidate and recheck. PR merge uses expected head and required up-to-date base/checks.

Bind repo/run/issue/PR, contract revision/digest, actual base and shard heads, integration commit and code tree digest, current generations, tooling sources/digest, checks and their completion, evaluator version and signed result, reviewed tree, findings/safeguard artifact digests, and applicable owner approvals. Ordinary enrolled PRs require their frozen gates. Policy activation additionally requires the whole campaign and external attestation. Scope the evidence to the obligation: an implementation receipt alone cannot mark the integrated work verified. Local mutable checkpoint statuses are projections. Missing, stale, expired, superseded or contradictory evidence fails closed.

Reviewer identity is descriptive metadata. Reusing a worker, model or reviewer session is permitted, including after a rejection. Reviews required by the contract must address the precise current tree. Preserve the owner-authenticated oracle mismatch workflow, the named disposition and regression test. A campaign cannot introduce or expand a parity exception. Never grant public or hidden qualification to a failing financial case by waiver.

### Verification reliability

For each evaluator or gate repair freeze a minimal counterexample, expected diagnostic and good control before changing the implementation. On clean disposable snapshots the old gate must exhibit the specific false GO, the repaired gate must reject that input for the intended reason, and both must accept the good control. For a product fix the incumbent must exhibit the specified defect and the candidate must satisfy the same oracle. For new safeguards extend existing fixture substitution across layers. Infrastructure errors, missing fields, crashes and timeouts are inconclusive. A reproduction on a different tree cannot close the finding.

Tier 0 checks test and evaluator diffs against trusted base manifests for added skips/only/ignores, assertion deletion, omitted cases, weaker thresholds, changed oracle/fixtures and altered command/exit handling. Unknown semantic changes to protected code require owner-scoped review and red proof. Expiring owner waivers name exact diff, rule, rationale and replacement evidence. Waivers cannot remove acceptance criteria. Test the guard itself using known corruptions and good refactors.

Findings carry ID, canonical theme, severity, observation/assumption, implicated path and tree, evidence ID, protected invariant, disposition and resolution. Pure review-rule precedence: missing owner decision → clarify, budget/round cap or repeated blocker set without new evidence → escalate, new/fix-induced blocker → iterate, all required findings resolved and checks valid → pass to next obligation. A frozen severity/impact threshold selects a cheap deterministic reproduction if a finding is ambiguous or its fix consumes the remaining repair allowance. If still ambiguous, ask the owner or fund a single investigation. No panel, no extra call for already reproduced defects.

### Private evaluation boundary

Phases 0–2 can ship and run in shadow without private runner provisioning. For Phase 3 the cheapest acceptable starting option, if available, is an existing owner-controlled remote Linux host capable of isolating disposable VMs. Otherwise rent an on-demand VM host for qualification windows only. Provision from a separate trusted device and identity. Evaluator administrative, recovery, pack-decryption and signing credentials must never touch the shared Windows machine. Its owner-authenticated gh session must have no direct or indirect authority over private workflows, runner images, secrets, packs or signing policy. A separate account reachable through that session also fails isolation. The local broker may nominate a candidate through a limited submission interface. Verify those boundaries before enabling promotion.

Use an owner-controlled **remote Linux runner** on separate credentials, on demand. The shared Windows login can start WSL instances, access mounted volumes and control Docker. A directory under ProgramData, another Linux user or a second distro under that login cannot establish holdout secrecy. Continue public development gates in KhitmeeERPNext. Host only public verification keys and aggregate attestations locally. Separate the coordinator broker from the worker OS principal as well: T3 workspaces and child prompts are organizational boundaries only. Until a worker runs without broker credentials, write access to the ledger or access to the evaluator, use shadow mode.

Owner stores versioned encrypted packs, pinned stock ERPNext/Frappe DB snapshots and evaluator image in a private account. An owner-controlled controller fetches a nominated immutable Git tree, verifies its digest and launches a disposable candidate VM. The guest gets the minimum individual scenario inputs through ordinary application calls and a disposable database. Private manifest, seed generator, expected answers, stock oracle process, signer and other cases stay outside the guest. No worker access, shared mounts, Docker socket, cloud metadata credentials, outbound network or public candidate logs. Destroy guests and scratch DBs after each arm. Candidate code can observe its own requests, so qualification depends on fresh cases and coarse feedback too.

Use public/dev, stable private validation, and a sealed rotating confirmation pack. Vary dates, warehouses, items, permission roles, linked returns, precision and valuation reposts. Check complete row sets, exact stock-defined value/rounding per field, permissions, ledger and voucher invariants. Use an independently reset stock snapshot. Seasonal micro-probes vary workload mix and windows, attest the complete isolated 2 GiB/two-vCPU guest, cold/warm state, restart counts and sample coverage. Compare per-class tails across predeclared interleaved repetitions. Smoke cannot qualify. Pin machine/image and noise limits. Unstable controls yield inconclusive.

Controller signs canonical result bytes (Ed25519 via isolated signer) containing repo, nonce, campaign, epoch, arm, task-manifest commitment, tree/commit, contract, evaluator/tooling/pack digests, environment fingerprint, coarse invariant verdicts, coverage, issue/expiry times and key ID. Broker pins owner-authorized public keys, rejects revoked keys, wrong bindings, reused nonces and expired results. Private seeds have high entropy and commitments are salted. Detailed traces stay private. Rotation means a new epoch and fresh incumbent baseline: rotate at least monthly while active, after suspected disclosure, or before a second finalist sees the same confirmation pack. One hidden submission per finalist; record negative and inconclusive submissions. Score incumbent and finalist together. Predeclare allowable public/private per-class gain divergence from control repetitions. Public improvements accompanied by hidden regressions, unseen-case failures, or divergence exceeding that bound quarantine the proposal. Owner examines private diagnostics.

### Campaigns, scheduling and rollback

At closeout, join receipts, gates and findings, verify linked evidence, deduplicate lessons and propose one scoped change referencing an incumbent, hypothesis and expected effect. The adopted policy governs the next enrolled run, which can yield a new proposal. Order the surfaces: compact briefs/retrieval first (same models), routing next, then retry/review parameters within frozen ceilings, then additive safeguards with red proofs. Evaluator code, signing, owner authority and hard acceptance criteria are outside candidate authority. Workers may file public evaluator counterexamples or propose public fixes. The owner commissions private evaluator changes separately, runs old/new controls against archived regressions and fresh cases, starts a new epoch and rebaselines. Never score a candidate using its own tooling overlay.

Freeze before screening: corpus and full assignment denominator, disjoint development/confirmation tasks, incumbent tree, task classes and difficulty, seeds where supported, model versions/settings, caps, gate commands, practical gain and uncertainty rule, pack/evaluator/brief versions and rollback horizon. One parent incumbent per campaign, at most two historical screening rounds, one finalist paired replay, depth one (no campaign spawning), at most one activation per seven days. Persist rejected lineage and invalidate descendants of withdrawn evidence. Hard default campaign budget zero until the owner binds a numerical token and currency ceiling for the entire proposal plus both replay arms. Expensive requests must fit outstanding reservations. Exhaustion yields no decision to promote.

Replay all preassigned pairs on fresh worktrees at identical task snapshots, model assignments, per-task budgets and correctness criteria. Alternate arm order with a recorded random seed. Keep failures, stalls, retries and review costs in the denominator. Historical scores screen only. For later routing trials, freeze identical task × model cells in both arms and compare policies on a common measured outcome matrix including escalation costs. Unsupported counterfactual routes remain unevaluated. No model substitution inside an efficiency comparison.

Require every previously completed task to complete, all hard gates and hidden controls to pass, no observed escaped defect or security regression, and a measurable token gain with no cost increase. For the first trial predeclare a 10% practical saving and a positive lower 95% paired interval on savings across task units (stratified paired bootstrap with fixed seed and adequate sample size established on controls). Test 50% separately. Too few pairs, unobserved total usage, degraded completion, or a noisy result retains the incumbent. Record elapsed time and review minutes. Owner authenticates activation for the exact tuple; atomically advance a versioned incumbent pointer at next campaign boundary. Pin active runs. On subsequently confirmed escaped defect, changed trust root or failed canary, freeze dispatch, revoke affected evidence and restore the last qualified predecessor under compatible epoch or suspend until requalification. Rollback never erases receipts.

Keep coordinator-triggered dispatch. Tier 0 computes ready dependencies, checks approval, claims, budgets and acquires all required lanes in fixed order with bounded nonblocking attempts and release-on-conflict. Use existing host-wide Windows lease authority for KhitmeeERPNext stack and host timing. Also serialize oracle capacity and policy activation. Queue lease waits without strikes. Infrastructure faults get a separate capped backoff budget; semantic failures consume existing strikes. Unknown errors pause after one classification attempt.

Reconsider a Symphony-style daemon only after three enrolled runs measure at least an hour each of avoidable coordinator dispatch/recovery time and the admission/kill tests pass. Owner must explicitly enable it. Poll only explicitly enrolled GitHub issues with current authenticated owner approval and published contract. Reconcile closure, dependencies, revoked approvals, active T3 requests and expired claims before dispatch. Maintain one idempotently updated workpad per issue with run, tree, outstanding gates, leases, cost and owner action. The comment is informational. Broker holds scoped GitHub credentials. No auto-enrollment or recursive issue creation. Enforce per-issue/day quotas, a host kill switch and owner revocation on each tick. PR closure alone cannot complete a run.

## Alternatives rejected

* Defer a Rust rewrite. In the coordinator's 5.15-second shard check, 4.98 seconds elapsed in subprocess waits. Eliminating all 0.17 seconds of Python time would save about 3.3% on that sample. Measure reuse of deterministic subprocess results first.

* Mandatory fresh reviewers, distinct models, pre-freeze panels and verification panels spend tokens without demonstrating which defect they prevent. The owner may use one optional pass. Requiring exact-tree evidence costs no additional model when the tree is unchanged.
* An LLM judge, live self-edits to the verifier and model-authored success labels create circular evidence. Use executable checks and an external signature.
* An always-on optimizer, Evo top-K population, per-shard DAG hierarchy, full CXDB event capture and a scheduler-first rollout raise operating costs before identifying the bottleneck. Retain paired comparison, generation fencing, deterministic admission and minimal evidence.
* Full agent framework replacement and blanket log compression duplicate T3 or hide important diagnostics. Retain raw evidence and measure each display optimization.

## Consequences

An enrolled run gains provenance even if telemetry is partial. Capability per token is measurable only for cohorts with comparable coverage. Provider quotas, private runner availability and the finite confirmation budget can leave a campaign inconclusive. Tier 0 consumes CPU, disk, operator time and runner minutes. Cap each in the frozen contract. An owner can keep normal development running without funding a campaign. Multi-model review and paid replay have no recurring default charge.

Existing-file wiring belongs exclusively to the named integration shard, delivered in small commits at each dependency boundary. Token estimates are **additional recurring** model work; implementation effort is one-time.

## Safety invariants

| Checkable rule | Enforcement |
|---|---|
| Only the owner authorizes scope, activation and automatic merge. | Validate current authenticated comments and applicable owner label events, exact policy paths/revision, expected refs and active pointer at publication. |
| A candidate cannot grade itself or publish stale evidence. | Base-pinned trusted verifier, private signer, generation compare-and-swap and identical target predicate in CI/recovery. Worker ledger writes denied. |
| Every paid start has an enforceable reservation. | Central transactional admission, per-run/campaign ceilings, deny unknown bounds, fence revoked work, retain late spend. |
| Efficiency cannot weaken checks, hide failures or lose any previously completed task. | Frozen full assignment manifest, same-model pairs, raw logs and per-task completion bitmap, mandatory public/live and private checks. Null telemetry blocks savings claims. |
| Exact parity and workload-specific safety survive every promotion. | Stock oracle, complete rows and per-field precision, per-class metrics, attested environment and red/green controls. No aggregate score offsets a failure. |
| Hidden feedback and recursion are bounded. | Private packs, per-pack submission counter, rotation, depth/round caps, seven-day activation limit and predecessor pointer. |
| Every review applies to its tree regardless of who performed it. | Receipt/evidence hash and tree binding, identity excluded from admission and review predicates. |

## Verification

Run a shadow baseline before comparing policy versions. Report assigned and verified task counts, completion bitmap, tokens and cost per verified task (all failed efforts included; undefined at zero completions), cached-read/input fraction, repeated blob/span reads, retries without new evidence, confirmed escaped defects, telemetry coverage and per-class public/private results. Track defects discovered after qualification over a frozen follow-up window; zero observed is a target, not proof of absence. Reopen and roll back when a later finding invalidates qualification.

Use offline fixtures for transition, signing and race tests. Run the existing offline fast-check for implementation changes. For financial qualification use `python tools/perf_parity.py --require-db` with stock ERPNext and the external hidden comparison. Test host timing under the resource lease, including a disturbed control run. The ADR itself changes no runtime behavior.

* **UNCERTAIN — observability and hard limits.** Inspect actual T3, Codex and Devin payloads, quota enforcement and cancellation billing on an already-funded task. Publish a field-by-provider coverage table. Missing counters stay unknown.
* **UNCERTAIN — which context intervention pays.** Measure Phase 0 sinks first. Compare raw/RTK output and compact briefs on fixed tasks, include cache hits, full failures and rediscovery reads. If repeat reads are immaterial, defer the brief trial and seek a revised hypothesis.
* **UNCERTAIN — affordable statistical power and host fidelity.** Use incumbent-only existing data and deterministic control reruns to size matched tasks and calibrate noise/divergence bounds before freezing the campaign. Validate local versus remote per-class seasonal controls. Insufficient budget or fidelity means no activation.
* **UNCERTAIN — daemon economics.** Time coordinator waits separately from actual intervention on three runs. Implement continuous polling only if the measured threshold is met.
